# BMS Intercom

Интеграция Home Assistant для вызывной панели. Всё в одном
месте: входящий вызов → всплывающее окно с видео и звуком звонка → кнопки
**Ответить / Сбросить / Открыть дверь**. При ответе микрофон по умолчанию
выключен (push-to-talk).

Не требует browser_mod, webrtc-card или ручной правки дашборда — поп-ап
встроен в интеграцию и подгружается автоматически.

## Возможности

- 📞 **Автоматический поп-ап** при звонке на панель — на любом открытом дашборде.
- 📹 **Видео с панели** (RTSP → WebRTC/go2rtc, встроен в Home Assistant).
- 🔔 **Звук звонка** (встроенный, зацикленный).
- ✅ **Ответить / Сбросить** — команды уходят на панель по ISAPI, панель «понимает», что трубку подняли.
- 🚪 **Открыть дверь** — реле панели.
- 🎙️ **Микрофон выключен по умолчанию**, включается кнопкой (push-to-talk).
- 🧪 **Демо-режим** — виртуальная панель с генерируемым видеопотоком и кнопкой «Симулировать звонок» для настройки без оборудования.

## Установка

### Через HACS (рекомендуется)
1. HACS → Интеграции → ⋮ → **Custom repositories** → добавьте этот репозиторий (тип *Integration*).
2. Установите **BMS Intercom** и перезапустите Home Assistant.

### Вручную
Скопируйте `custom_components/bms_intercom` в `config/custom_components/` и перезапустите HA.

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → BMS Intercom**, затем
выберите режим:

### Демо-режим
Виртуальная панель без оборудования. Появятся сенсор «Вызов» и кнопки, включая
**Симулировать звонок** — нажмите, чтобы увидеть весь сценарий (поп-ап, видео,
ответ, дверь, сброс).

### Реальная панель
Поддерживаются вызывные панели (DS-KV…) и терминалы доступа с домофоном
(например **DS-K1T341AM**). Укажите параметры:

| Поле | Значение |
|------|----------|
| IP-адрес панели | например `192.168.70.121` |
| Логин / Пароль | учётная запись ISAPI (обычно `admin`) |
| HTTP порт (ISAPI) | по умолчанию `80` |
| RTSP порт | по умолчанию `554` |
| Номер реле двери | по умолчанию `1` |
| Видеоканал | `101` — основной поток, `102` — дополнительный |
| Поток событий (alertStream) | включён по умолчанию |

Интеграция проверит связь с панелью при добавлении (`/ISAPI/Security/userCheck`,
затем `/ISAPI/System/deviceInfo`). Авторизация — **HTTP digest**, посчитанный
самой интеграцией (RFC 2069/2617/7616, MD5/MD5-sess/SHA-256) в том же порядке
полей, что шлёт браузер: `algorithm` отправляется только если панель его
предложила, `uri` подписывается вместе с query-строкой, `opaque` возвращается дословно —
в том числе пустой (`opaque=""`), как его шлёт DS-K1T341AM V3.2.30, ответ на 401 уходит по
той же keep-alive TCP-сессии (прошивки Hikvision V3.x привязывают nonce к
соединению). Откат на basic — если панель предлагает только его.

## Проверка панели (диагностика)

Модели отвечают на разные эндпоинты ISAPI. Чтобы не гадать, у устройства есть
кнопка **«Проверить панель»** (и служба `bms_intercom.probe`): она опрашивает
все известные варианты и пишет отчёт в журнал Home Assistant и в атрибут
`probe_report` этой кнопки — по каждому адресу: HTTP-статус, тип содержимого и
первые 120 символов ответа. **Пароль в отчёт не попадает** (`://user:pass@`
заменяется на `://***@`).

```
BMS Intercom — проверка панели 192.168.70.121
  модель: DS-K1T341AM V3.2.30
  авторизация: digest (успешно)
  RTSP: rtsp://***@192.168.70.121:554/Streaming/Channels/101
   1. [OK  ] userCheck: GET  .../ISAPI/Security/userCheck  -> 200  auth=digest  application/xml  | <userCheck…
   7. [OK  ] snapshot:   GET  .../ISAPI/Streaming/channels/101/picture  -> 200  image/jpeg  | [12000 байт…]
  11. [FAIL] callStatus.json: GET .../ISAPI/VideoIntercom/callStatus?format=json -> 403 | Invalid Operation…
```

При 401 в отчёт добавляются: `challenge:` — заголовок `WWW-Authenticate`
панели дословно, и по строке на **каждую** попытку авторизации
(`без заголовка → 401`, `digest → 401`, `basic → 200`) с самим заголовком
`Authorization` — откат на basic не прячет то, что отправил digest. В digest
пароля нет, только хэш `response=`; basic показывается как `Basic ***`.

Отдельной строкой идёт прямое сравнение на `/ISAPI/Security/userCheck`
(эндпоинт, на котором панель проверяется браузером):
`проверка /ISAPI/Security/userCheck: digest → 200, basic → 401`.

Реле двери при проверке **не срабатывает**. Чтобы проверить и его, вызовите
службу с `test_door: true`.

Кнопки и сенсор остаются доступными, даже если панель не отвечает: состояние
вызова становится «неизвестно», а не `unavailable`, — иначе диагностику нечем
было бы запустить.

## Что создаётся

Устройство «Домофон» с сущностями:

| Сущность | Назначение |
|----------|-----------|
| `camera` Видео | поток с панели |
| `binary_sensor` Вызов | активен во время звонка (атрибут `call_state`: idle/ringing/answered) |
| `button` Ответить / Сбросить / Открыть дверь | управление |
| `button` Проверить панель | диагностика ISAPI (отчёт в журнал и в атрибуты) |
| `button` Симулировать звонок | только в демо-режиме |

## Двусторонний звук и микрофон (HTTPS) — автоматически

Видео и приём звука работают через встроенный в Home Assistant **go2rtc**.
Микрофон оператора по умолчанию выключен и включается кнопкой (push-to-talk).

Браузер разрешает микрофон только в защищённом контексте (HTTPS). Поэтому
интеграция **сама поднимает локальный HTTPS** — ничего настраивать не нужно:

- при запуске генерируется самоподписанный сертификат (SAN на все локальные
  адреса и имена Home Assistant);
- поднимается лёгкий reverse-proxy на отдельном порту (по умолчанию `8443`),
  который проксирует весь HA (страница, WebSocket, видео);
- поп-ап вызова, открытый по http, сам показывает кнопку **«Открыть по HTTPS»**
  на `https://<ваш-адрес>:8443`.

От вас — только **IP/логин/пароль панели**. Единственное, что нельзя
автоматизировать, — браузер один раз попросит принять самоподписанный
сертификат («Дополнительно → Перейти»).

Порт можно сменить, а также задать готовый внешний HTTPS-адрес (Nabu Casa и т.п.)
в **Настройки → Устройства и службы → BMS Intercom → Настроить**. Если хотите
HTTPS **без предупреждений** (локальный доверенный сертификат) — см.
[docs/local-https.md](docs/local-https.md).

## Как это устроено

```
Вызывная панель
   ├── RTSP  /Streaming/Channels/101 ──► go2rtc (в HA) ──► camera ──► поп-ап
   ├── ISAPI /Event/notification/alertStream ──► события вызова ──► binary_sensor
   │         (если модель не умеет — опрос /VideoIntercom/callStatus)
   └── ISAPI /AccessControl/RemoteControl/door/N ◄── кнопка «Открыть дверь»
```

Порядок перебора эндпоинтов (первый ответивший запоминается):

| Что | Варианты по порядку |
|-----|---------------------|
| RTSP | `/Streaming/Channels/101` → `/102` → `/1` (устаревший) |
| Снимок | `/ISAPI/Streaming/channels/{101,102,1}/picture` → `…/httpPreview` |
| Дверь | `PUT /ISAPI/AccessControl/RemoteControl/door/N` (XML) → тот же `?format=json` → `/ISAPI/VideoIntercom/unlock/N` |
| Вызов | `alertStream` → `/ISAPI/VideoIntercom/callStatus?format=json` → без `format` → `callSignal` |
| Ответ/сброс | `PUT /ISAPI/VideoIntercom/callSignal` (json → xml); если модель их не имеет, команда пропускается без ошибки |

## Статус разработки

| Этап | Что | Статус |
|------|-----|--------|
| 1 | Каркас, демо-режим, сенсор и кнопки | ✅ |
| 2 | Видео (демо-поток + реальный RTSP/go2rtc) | ✅ |
| 3 | ISAPI: статус вызова, ответ/сброс, дверь | ✅ |
| 4 | Поп-ап со звуком звонка и mute микрофона | ✅ |

| 5 | Digest-авторизация, перебор эндпоинтов, alertStream, диагностика | ✅ |

> Реальный режим реализован по спецификации ISAPI и проверен на мок-панели
> (`tests/`). При первом подключении к физическому устройству нажмите
> **«Проверить панель»** — отчёт в журнале покажет, какие эндпоинты эта
> прошивка действительно поддерживает.

Весь текст в интерфейсе (поп-ап, подписи) использует **родной шрифт Home
Assistant** — ничего не бандлится.

Иконка и логотип интеграции лежат в `custom_components/bms_intercom/brand/` и
показываются Home Assistant напрямую (требуется HA 2026.3+; PR в каталог
home-assistant/brands не нужен).
