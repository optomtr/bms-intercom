# BMS Intercom

Интеграция Home Assistant для вызывной панели (DS-KV…) и терминала доступа
с домофоном (DS-K1T341AM). Всё в одном месте: входящий вызов → поп-ап по
центру экрана с видео и **двусторонним звуком** → кнопки **Ответить / Открыть /
Сбросить**, как на телефоне.

Видео и приём звука идут через **встроенный в Home Assistant go2rtc**, а
микрофон оператора — напрямую через **ISAPI** панели. **Не нужны** ни
go2rtc-аддон, ни правки `configuration.yaml`, ни browser_mod / webrtc-card —
поп-ап встроен в интеграцию и подгружается автоматически.

## Возможности

- 📞 **Автоматический поп-ап** при звонке на панель — на любом открытом дашборде.
- 📹 **Видео + входящий звук** с панели (RTSP → WebRTC через встроенный go2rtc).
- 🎙️ **Микрофон → панель** через native ISAPI two-way audio (без go2rtc-аддона). Включён по умолчанию, как телефонный разговор; отключается кнопкой.
- 🔔 **Звук звонка** (встроенный, зацикленный; звучит только во время звонка — киоск-браузеры не проигрывают его сами).
- ✅ **Ответить / Сбросить** — по ISAPI; панель «понимает», что трубку подняли/положили (звонящий вызов — `reject`, идущий разговор — `hangUp`).
- 🔒 **Открыть** — реле двери; вызов завершается сам через 5 с (через 30 с, если уже идёт разговор).
- 👁️ **Просмотр** — переключатель открывает окно с живым видео и кнопками Открыть/Звук без звонка.
- 🩺 **Проверить панель** — диагностика ISAPI: какие эндпоинты есть у этой прошивки.
- 🧪 **Демо-режим** — виртуальная панель с генерируемым видеопотоком и кнопкой «Симулировать звонок» для настройки без оборудования.

## Установка

### Через HACS (рекомендуется)
1. HACS → Интеграции → ⋮ → **Custom repositories** → добавьте этот репозиторий (тип *Integration*).
2. Установите **BMS Intercom** и перезапустите Home Assistant.

### Вручную
Скопируйте `custom_components/bms_intercom` в `config/custom_components/` и перезапустите HA.

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → BMS Intercom**, затем
выберите режим:

### Демо-режим
Виртуальная панель без оборудования. Появятся сенсор «Вызов» и кнопки, включая
**Симулировать звонок** — нажмите, чтобы увидеть весь сценарий (поп-ап, видео,
ответ, дверь, сброс).

### Реальная панель
Поддерживаются вызывные панели (DS-KV…) и терминалы доступа с домофоном
(например **DS-K1T341AM**). Укажите параметры:

| Поле | Значение |
|------|----------|
| IP-адрес панели | например `192.168.70.121` |
| Логин / Пароль | учётная запись ISAPI (обычно `admin`) |
| HTTP порт (ISAPI) | по умолчанию `80` |
| RTSP порт | по умолчанию `554` |
| Номер реле двери | по умолчанию `1` |
| Видеоканал | `101` — основной поток, `102` — дополнительный |
| Поток событий (alertStream) | включён по умолчанию |

Интеграция проверит связь с панелью при добавлении (`/ISAPI/Security/userCheck`,
затем `/ISAPI/System/deviceInfo`). Авторизация — **HTTP digest**, посчитанный
самой интеграцией (RFC 2069/2617/7616, MD5/MD5-sess/SHA-256) в том же порядке
полей, что шлёт браузер: `algorithm` отправляется только если панель его
предложила, `uri` подписывается вместе с query-строкой, `opaque` возвращается дословно —
в том числе пустой (`opaque=""`), как его шлёт DS-K1T341AM V3.2.30.

**Nonce одноразовый.** Прошивка V3.x принимает каждый nonce ровно один раз и
на повторный отвечает обычным 401 (без `stale=true`). Поэтому каждый запрос
берёт собственный вызов: уходит без заголовка, а пришедший 401 тут же
получает ответ с `nc=00000001` и новым `cnonce`. Быстрый путь с
переиспользованием nonce есть, но выключен по умолчанию, ответ на 401 уходит по
той же keep-alive TCP-сессии (прошивки Hikvision V3.x привязывают nonce к
соединению). Откат на basic — если панель предлагает только его.

## Проверка панели (диагностика)

Модели отвечают на разные эндпоинты ISAPI. Чтобы не гадать, у устройства есть
кнопка **«Проверить панель»** (и служба `bms_intercom.probe`): она опрашивает
все известные варианты и пишет отчёт в журнал Home Assistant и в атрибут
`probe_report` этой кнопки — по каждому адресу: HTTP-статус, тип содержимого и
первые 120 символов ответа. **Пароль в отчёт не попадает** (`://user:pass@`
заменяется на `://***@`).

```
BMS Intercom — проверка панели 192.168.70.121
  модель: DS-K1T341AM V3.2.30
  авторизация: digest (успешно)
  RTSP: rtsp://***@192.168.70.121:554/Streaming/Channels/101
   1. [OK  ] userCheck: GET  .../ISAPI/Security/userCheck  -> 200  auth=digest  application/xml  | <userCheck…
   7. [OK  ] snapshot:   GET  .../ISAPI/Streaming/channels/101/picture  -> 200  image/jpeg  | [12000 байт…]
  11. [FAIL] callStatus.json: GET .../ISAPI/VideoIntercom/callStatus?format=json -> 403 | Invalid Operation…
```

При 401 в отчёт добавляются: `challenge:` — заголовок `WWW-Authenticate`
панели дословно, и по строке на **каждую** попытку авторизации
(`без заголовка → 401`, `digest → 401`, `basic → 200`) с самим заголовком
`Authorization` — откат на basic не прячет то, что отправил digest. В digest
пароля нет, только хэш `response=`; basic показывается как `Basic ***`.

Отдельной строкой идёт прямое сравнение на `/ISAPI/Security/userCheck`
(эндпоинт, на котором панель проверяется браузером):
`проверка /ISAPI/Security/userCheck: digest → 200, basic → 401`.

Реле двери при проверке **не срабатывает**. Чтобы проверить и его, вызовите
службу с `test_door: true` — тогда в отчёте появится строка вида
`реле двери: ОТКРЫТА командой door.xml (HTTP 200)`. **Дверь при этом
физически откроется**, поэтому делайте это с ведома владельца.

Кнопки и сенсор остаются доступными, даже если панель не отвечает: состояние
вызова становится «неизвестно», а не `unavailable`, — иначе диагностику нечем
было бы запустить.

## Что создаётся

Устройство «Домофон» с сущностями:

| Сущность | Назначение |
|----------|-----------|
| `camera` Видео | поток с панели |
| `binary_sensor` Вызов | активен во время звонка (атрибут `call_state`: idle/ringing/answered) |
| `button` Ответить / Сбросить / Открыть дверь | управление |
| `button` Проверить панель | диагностика ISAPI (отчёт в журнал и в атрибуты) |
| `switch` Просмотр | открыть/закрыть окно живого просмотра без звонка |
| `button` Симулировать звонок | только в демо-режиме |

## Двусторонний звук и микрофон (HTTPS) — автоматически

- **Видео и приём звука** (посетитель → оператор) идут через встроенный в Home
  Assistant **go2rtc** — настраивать ничего не нужно.
- **Микрофон** (оператор → панель) интеграция отдаёт напрямую через **ISAPI
  two-way audio** панели: браузер кодирует звук в G.711 µ-law и шлёт его по
  WebSocket (`bms_intercom/talk_start|talk_data|talk_stop`), интеграция
  передаёт его панели. Кодек панели интеграция сама ставит в G.711.

Микрофон включён по умолчанию (как телефонный разговор) и отключается кнопкой.

## Поп-ап

Окно по центру экрана размером с видео; поверх видео — имя домофона, статус,
таймер разговора, кнопки и дата-время. Три режима:

| Режим | Когда | Кнопки |
|-------|-------|--------|
| Входящий вызов | панель звонит | Сбросить · Ответить · Открыть |
| Разговор | после «Ответить» | Сбросить · Открыть · Микрофон |
| Просмотр | переключатель «Просмотр» | Открыть · Звук; закрытие — крестик или фон |

После «Ответить» поп-ап держится до «Сбросить» (не дольше 3 минут), даже если
панель сразу рапортует `idle`; начавшийся звонок держится хотя бы 25 с, даже
если панель быстро бросила вызов. Рингтон и снимок грузятся с Home Assistant,
поэтому работают и в киоске, открытом как `file://`.

Браузер разрешает микрофон только в защищённом контексте (HTTPS). Поэтому
интеграция **сама поднимает локальный HTTPS** — ничего настраивать не нужно:

- при запуске генерируется самоподписанный сертификат (SAN на все локальные
  адреса и имена Home Assistant);
- поднимается лёгкий reverse-proxy на отдельном порту (по умолчанию `8443`),
  который проксирует весь HA (страница, WebSocket, видео);
- поп-ап вызова, открытый по http, сам показывает кнопку **«Открыть по HTTPS»**
  на `https://<ваш-адрес>:8443`.

От вас — только **IP/логин/пароль панели**. Единственное, что нельзя
автоматизировать, — браузер один раз попросит принять самоподписанный
сертификат («Дополнительно → Перейти»).

Порт можно сменить, а также задать готовый внешний HTTPS-адрес (Nabu Casa и т.п.)
в **Настройки → Устройства и службы → BMS Intercom → Настроить**. Если хотите
HTTPS **без предупреждений** (локальный доверенный сертификат) — см.
[docs/local-https.md](docs/local-https.md).

## Профиль DS-K1T341AM V3.2.30 (проверено на железе)

| Возможность | Как есть | Что делает интеграция |
|---|---|---|
| Видео | `/Streaming/Channels/101` (и `102`), `/1` — 404 | RTSP-поток через go2rtc |
| Снимок | все `…/picture` и `httpPreview` — 404 | кадры берутся из потока (`use_stream_for_stills`) |
| Вызов | `alertStream` — 404, `callStatus?format=json` — 200 | опрос раз в секунду, тело `{"CallStatus":{"status":"…"}}` |
| Ответ/сброс | `callSignal` — 404 | кнопки меняют только состояние в HA, атрибут `answer_supported: no` |
| Дверь | GET `…/door/1/capabilities` — 405, но PUT работает | `PUT …/RemoteControl/door/1` с XML-телом |

Вердикт про поток событий запоминается в записи конфигурации: после первого
404/405 интеграция больше не тратит на него перезапуски и сразу идёт опросом.
Пока поток не подтверждён, опрос `callStatus` идёт параллельно — звонок не
теряется. Недоступная панель (обрыв сети, питание) — это не «не
поддерживается»: опрос делает паузу 10 с и продолжает, а не выключается.

**Кнопка вызова без адресата.** Если на панели не задан SIP-сервер и главная
станция (Intercom → Linked Network: 0.0.0.0), вызов не начинается и
`callStatus` остаётся `idle`. Тогда нажатие ищется в журнале событий
терминала: «Проверить панель» показывает записи `AcsEvent` за последние
15 минут (по часам самой панели) и документы `httpHosts` — может ли панель
сама присылать события на адрес Home Assistant.

## Как это устроено

```
Вызывная панель
   ├── RTSP  /Streaming/Channels/101 ──► go2rtc (в HA) ──► camera ──► поп-ап (видео + входящий звук)
   ├── ISAPI /Event/notification/alertStream ──► события вызова ──► binary_sensor
   │         (если модель не умеет — опрос /VideoIntercom/callStatus)
   ├── ISAPI /AccessControl/RemoteControl/door/N ◄── кнопка «Открыть дверь»
   └── ISAPI /System/TwoWayAudio/channels/N/audioData ◄── микрофон оператора (G.711 по WebSocket)
```

Порядок перебора эндпоинтов (первый ответивший запоминается):

| Что | Варианты по порядку |
|-----|---------------------|
| RTSP | `/Streaming/Channels/101` → `/102` → `/1` (устаревший) |
| Снимок | `/ISAPI/Streaming/channels/{101,102,1}/picture` → `…/httpPreview` |
| Дверь | `PUT /ISAPI/AccessControl/RemoteControl/door/N` (XML) → тот же `?format=json` → `/ISAPI/VideoIntercom/unlock/N` |
| Вызов | `alertStream` → `/ISAPI/VideoIntercom/callStatus?format=json` → без `format` → `callSignal` |
| Ответ/сброс | `PUT /ISAPI/VideoIntercom/callSignal` (json → xml), `answer` / `reject` / `hangUp`; если модель их не имеет, команда пропускается без ошибки |

## Статус разработки

| Этап | Что | Статус |
|------|-----|--------|
| 1 | Каркас, демо-режим, сенсор и кнопки | ✅ |
| 2 | Видео (демо-поток + реальный RTSP/go2rtc) | ✅ |
| 3 | ISAPI: статус вызова, ответ/сброс, дверь | ✅ |
| 4 | Поп-ап со звуком звонка и mute микрофона | ✅ |
| 5 | Digest-авторизация, перебор эндпоинтов, alertStream, диагностика | ✅ |
| 6 | Видео через WebRTC, микрофон через ISAPI two-way audio, новый поп-ап, «Просмотр» | ✅ |

> Двусторонний звук (go2rtc для видео + native ISAPI для микрофона) проверен
> на физической **DS-KV6113**; профиль DS-K1T341AM — выше. При первом
> подключении к другому устройству нажмите **«Проверить панель»** — отчёт в
> журнале покажет, какие эндпоинты эта прошивка действительно поддерживает.

Встроенный HTTPS-прокси вырезает присланные клиентом `X-Forwarded-*`,
`Forwarded` и `X-Real-IP` и сам их **не ставит**: Home Assistant видит его как
localhost, поэтому `use_x_forwarded_for`/`trusted_proxies` в `http:` не нужны
(с `X-Forwarded-For` без них HA отвечает 400). Cookies и прочие заголовки
пересылаются одинаково в HTTP и WebSocket — Ingress аддонов работает.

Весь текст в интерфейсе (поп-ап, подписи) использует **родной шрифт Home
Assistant** — ничего не бандлится.

Иконка и логотип интеграции лежат в `custom_components/bms_intercom/brand/` и
показываются Home Assistant напрямую (требуется HA 2026.3+; PR в каталог
home-assistant/brands не нужен).
